# Pane Tiling — Hyprland Visual/Motion Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the shipped multi-pane-tiling feature's visual and motion language up to the Hyprland-inspired design approved in `docs/superpowers/specs/2026-07-29-pane-tiling-hyprland-polish-design.md` — ambient glow, wider gaps, a real focus glow, drag-to-resize panes, a decoupled floating chrome pill/circle, smooth push-and-squeeze reflow, and a Dynamic-Island-style morph for the command island.

**Architecture:** Almost all of this is CSS and two React components (`PaneGrid.tsx`, `PaneChrome.tsx`) plus `AppShell.tsx`'s render tree. One new pure-logic function (`resizeSplit`) is added to `paneLayout.ts` following its existing immutable-tree-update pattern. One new dependency (Framer Motion) is added for the two genuinely new animation mechanics (reflow, island morph) — everything else is plain CSS transitions.

**Tech Stack:** React 19, TypeScript, Vite, Vitest, Framer Motion (new), hand-written CSS (`darkwood.css`) — no Tailwind, no other UI framework.

## Global Constraints

- Gap between tiled panes: 8px (not the 18px shown in one early mockup — the user explicitly asked to keep it smaller).
- Resize is mouse-only in this pass — no keybind equivalent, by explicit user decision. Do not add one.
- A manually-dragged split ratio must persist as a durable value on that `SplitNode` — an unrelated structural change elsewhere in the tree (opening/closing a pane in a different branch) must not reset it. `rebalance()` is only ever invoked by `splitAuto`/`splitDirectional`/`removePane` on the subtree they're actually restructuring — a resize goes through `resizeSplit` alone, which never calls `rebalance()`, so this is satisfied by construction; don't introduce a code path that calls `rebalance()` on a node purely because a sibling elsewhere changed.
- All new animations use only `transform`/`opacity` — never tween `width`, `height`, `top`, or `left` directly (standing performance goal: Grove should be meaningfully more optimized than Discord, not just "animated").
- No Tailwind, no CSS-in-JS — new styles go in `grove_client/src/styles/darkwood.css`, following its existing custom-property convention (reuse existing `--leaf-bright`, `--surface-*`, `--dur-*`, `--ease-out`, `--z-panel` tokens; don't invent new ones unless a task explicitly says to).
- Every task must leave `cd grove_client && npx tsc -b && npx eslint . && npm run test` clean (same baseline as the rest of this branch: 6 pre-existing errors / 2 pre-existing warnings, none introduced by this plan — verify by comparing against the branch's current HEAD before your task's changes, the same way prior tasks on this branch have).
- Git identity stays `richtofen <richtofen@grove.dev>`, no AI/Claude attribution anywhere, never `git add -A`/`git add .` (this repo has untracked AI-tooling directories that must never be staged).

```ts
export type SplitPath = ("a" | "b")[];

const MIN_SPLIT_RATIO = 0.15;
const MAX_SPLIT_RATIO = 0.85;

export function resizeSplit(root: PaneTreeNode, path: SplitPath, ratio: number): PaneTreeNode {
    if (path.length === 0) {
        if (root.type !== "split") return root;
        const clamped = Math.min(MAX_SPLIT_RATIO, Math.max(MIN_SPLIT_RATIO, ratio));
        return { ...root, ratio: clamped };
    }
    if (root.type === "leaf") return root;
    const [head, ...rest] = path;
    return head === "a"
        ? { ...root, a: resizeSplit(root.a, rest, ratio) }
        : { ...root, b: resizeSplit(root.b, rest, ratio) };
}
```

import { getLeaves, resizeSplit, type PaneContent, type PaneTreeNode, type SplitPath } from "../../paneLayout";

export const KIND_ACCENT: Record<PaneContent["kind"], string> = {
    channel:      "var(--leaf-bright)",
    dm:           "#5a9bd8",
    notification: "#d8a545",
    details:      "#a56ad8",

export interface PaneGridProps {
    root:          PaneTreeNode;
    chromeState:   "state2" | "state3";
    focusedPaneId: string | null;
    pillHovered:   boolean;
    onFocusPane:   (paneId: string) => void;

type PaneNodeProps = {

function PaneNode({
    node, path, indexById, chromeState, focusedPaneId, pillHovered, onFocusPane, onHoverPane, onOpenDetails, onClosePane, onResizeSplit, renderContent,

    const containerRef = useRef<HTMLDivElement | null>(null);

            <div className={`pane-split pane-split-${node.axis}`} ref={containerRef}>

                    axis={node.axis}
                    containerRef={containerRef}

function SplitDivider({
    axis, containerRef, onResize,
}: {
    axis: "row" | "column";
    containerRef: React.RefObject<HTMLDivElement | null>;
    onResize: (ratio: number) => void;
}) {
    function handlePointerDown(e: React.PointerEvent<HTMLDivElement>) {
        e.preventDefault();
        const container = containerRef.current;
        if (!container) return;
        e.currentTarget.setPointerCapture(e.pointerId);

        function handleMove(moveEvent: PointerEvent) {
            const rect = container.getBoundingClientRect();
            const ratio = axis === "row"
                ? (moveEvent.clientX - rect.left) / rect.width
                : (moveEvent.clientY - rect.top) / rect.height;
            onResize(ratio);
        }
        function handleUp() {
            window.removeEventListener("pointermove", handleMove);
            window.removeEventListener("pointerup", handleUp);
        }
        window.addEventListener("pointermove", handleMove);
        window.addEventListener("pointerup", handleUp);
    }

    return (
        <div className={`pane-split-handle pane-split-handle-${axis}`} onPointerDown={handlePointerDown}>
            <div className="pane-split-handle-bar" />
        </div>
    );
}
